# 设计思想

本文说明这个产品为什么长成现在这样。改设计时先回到这里：一个改动如果和这里的判断冲突，要么改掉改动，要么明确改掉这里的判断，并记到 [决策记录](10-decisions.md)。

## 产品是什么

**一个能看、能听、能说的助手，运行在你自己的设备上。**

产品分阶段交付。第一阶段各端只有看图模型和文字对话，全能模型和实时会话是下阶段，本文的目标不变，见 [交付阶段和两条基线](03-structure.md#交付阶段和两条基线)。

MiniCPM 面向端侧 omni 和 vision 模型，帮普通人处理生活里隐私优先的小事：看懂一份体检报告，核对一张发票，对着一盆植物问问题，一边操作屏幕一边讨论。

三件事决定了它和云端助手不同：

| 事实 | 对设计的影响 |
|---|---|
| 模型在用户设备上 | 隐私是可以被看见的产品能力。同时有下载、内存、发热、电量这些云端产品没有的状态 |
| 模型可以全双工 | 用户和模型可以同时说话。界面要表达“谁在说”和“谁在听”，而不是“录音/停止” |
| 用户不懂技术 | 默认界面不出现参数和架构词。手动控制保留，但放在安静的入口后面 |

## 用户和场景

**主要用户**是不关心模型的普通人。他们有一件具体的小事，不想把内容传给别人。他们会在厨房、车里、医院走廊、办公桌前使用，一只手拿着手机，或者一边做别的事一边说话。

**次要用户**是愿意调参数的进阶用户和开发者。他们能找到高级设置，但界面不为他们优化默认路径。

**一次典型使用**很短：打开、说一句或拍一张、得到结果、离开。所以第一屏就是可以开口的对话，不是列表、不是仪表盘。

## 八条原则

### 1. 让隐私被看见

隐私要在使用时能感知，只写在政策里没有用。

- 处理位置始终可见：新对话写明“只在这台设备上处理”，对话详情第一项是处理位置，实时画面上写着“本机处理”。
- 正在采集时一定有信号，没在采集时一定能确认没在采集。暂停时写“没有在听”。
- 内容离开设备是例外：联网搜索逐次询问；在线备用默认关闭，开启前说明并取得同意，之后每次都看得见。事后都能查。详见 [隐私设计](08-privacy.md)。
- 记住了什么也要看得见：写入时对话里留一行，当场能撤销。

### 2. 说人话，细节在后面

默认界面用结果和后果说话，技术词放到高级设置和“显示技术信息”开关之后。

| 不说 | 说 |
|---|---|
| 量化、KV Cache、n_ctx | 对话记忆长度 |
| 显存不足 | 资源快用完了，实时会话可能中断 |
| 帧率 1 fps | 每秒看 1 帧 |
| 模型推理中 | 正在回应 |

参数仍然完整保留，因为端侧用户确实可能需要为自己的设备做取舍。常用取舍先收进“省电 / 均衡 / 细致”。

模型规格是例外：用“轻量”“完整”这样的词来选，旁边用小字标 Q4、F16，让懂的人能对上。“量化”这个词本身仍然不进默认界面。

### 3. 表达同时在场

实时会话是两个人在同一段时间里各说各的。标志图形因此是双轨波形：上轨是你，下轨是模型，同一条时间轴。重叠区域就是打断。

打断是正常的交流方式，不是错误。模型被打断时让出话轮，转写里标“被你打断”。

### 4. 对话是唯一的容器

文字、语音、图片、文件、实时会话都发生在同一条对话里。

- 实时不是另一个页面：输入框变成控制条，对话继续滚动。
- 实时结束后，记录折叠留在对话里，文字可以接着聊，并带上上下文。
- 手机上对话就是根页面，历史记录在它的上一层。设备一次只跑得动一件事，所以不把多任务当成主要结构。

### 5. 诚实对待设备

端侧有物理限制。设计不掩盖，也不把责任交给用户。

- 下载、载入、发热、低电量都有明确状态。
- 能力分步下降并说明原因：发热时先放慢看画面，再只用声音，最后才暂停。不会悄悄变差，也不会一步断掉。
- 看不到的代价要翻译成用户能决定的话：“响应会变慢，设备会更凉快”。
- 模型也会读错。从图片读出的数字能一步对照原图，看不清时直接说看不清。

### 6. 打断是常态，内容不丢

来电、切后台、耳机断开、断线、被系统回收，都是手机上的日常。

- 用户写的字、说过的话、已生成的回答，任何中断都保留。
- 中断之后，采集只在用户点了之后恢复。设备不会在没人看着的时候重新开始听。
- 记录里留下空白标记，比如“来电 · 暂停了 1 分 12 秒”。转写不假装连续。
- 能撤销就不弹确认。

### 7. 克制的主动

全双工让模型可以先开口，这是能力，也是打扰。

- 主动提醒有预算：两次之间有冷却时间，由场景决定默认频率。
- 用户在提醒出现的当下就能说“少提醒”，立刻生效。
- 被压住的提醒计数可见，用户知道它忍住了几次。

### 8. 外壳归平台，语义归产品

最终是四端原生 UI。导航、列表、开关、菜单、弹窗、系统栏都用平台自己的控件和样式，不在原生端模拟一套品牌皮肤。

跨端有明确的先后：**平台原生优先，其次操作逻辑接近，最后才是颜色和风格接近。** 不要求像素级一致。操作逻辑指入口在哪、走几步、控件什么顺序、返回回到哪里。平台控件做不到时，让操作逻辑让步，不改用自绘。Web 没有系统控件，所以向原生端的操作逻辑靠。

产品只保留平台给不了的东西：角色颜色的含义、双轨波形、实时控制条的结构、隐私信号、文案。详见 [平台落地](07-platforms.md)。

这条原则决定了原型的定位：**原型规定结构、状态和语义，不规定原生端的像素**。网页端是例外，它没有系统控件可以依靠，原型的样式就是它的最终样式。

## 取舍

设计里反复出现这些取舍，默认这样判断：

| 冲突 | 默认选择 | 理由 |
|---|---|---|
| 便利和隐私 | 隐私 | 这是用户选端侧的原因。恢复采集多点一下是可接受的代价 |
| 完整和简单 | 默认简单，入口完整 | 设置项现在保留得很全，用来验证设计。删减等团队讨论 |
| 平台原生和跨端接近 | 平台原生优先，其次操作逻辑接近，最后才是颜色和风格 | 用户比较的是自己手机上的其他应用，但同一件事在各端走法接近，换设备不用重新学 |
| 动效和电量 | 电量 | 实时会话时 GPU 已经很忙，界面动画不和模型抢资源 |
| 主动和安静 | 安静 | 宁可少说一句，不要在错误的时候开口 |

## 明确不做

- 不做任务看板、多会话并行，手机上尤其不做。
- 不在后台运行模型。需要算力的能力都在前台工作，应用不在前台时只留下系统提供的定时通知和备忘录。
- 不在默认界面展示模型指标。
- 不用拟人形象。模型的存在由声音、波形和文字表达，不需要头像和表情。
- 不做桌面窗口外壳、手机系统栏的原型模拟。这些交给原生端。
