## 本轮提议，等你确认

这些已经写进文档或原型，改起来都容易。

| 提议 | 理由 | 替代方案 |
|---|---|---|
| 联网搜索默认“每次询问” | 搜索词是唯一可能带用户信息离开的内容 | 默认关闭，更严格，但能力不可发现 |
| 手机第一版没有屏幕共享 | iOS 上后台没有 GPU，手机网页不支持 | 只在远程模式或 Android 上提供 |
| Android 第一版用静态配色 | 动态配色可能破坏朱砂的含义 | 动态配色 |
| 不用拟人形象 | 模型由声音、波形和文字表达，也减少过度信任 | 给模型一个形象 |
| 欢迎流程不要权限 | 用到时才问 | 一次要完 |
| 原生端破坏性操作用系统红色 | 让朱砂更专注于采集状态 | 全部用朱砂 |
| 降温回升保持自动 | 只是恢复用户同意过的采集范围；暂停之后才要点击 | 每次都要点击，更严格但很烦 |
| 去掉“默认模型”，合并成“当前模型” | 只剩一个模型时两个概念重复。下次打开沿用上次的 | 保留默认模型，作为打开时载入的那个 |
| 确认后立刻开始换，不等到发送时 | 等待在用户打字时就过去了 | 发送时才换，等待来得突然 |
| 需要别的模型时先问，不自动换 | 换模型影响所有对话，还要等待 | 自动换，少一步但用户不知道发生了什么 |
| 载不下时换回原来的模型 | 用户不会落到没有模型可用的状态 | 停在未载入状态，等用户处理 |
| 定时任务用当前模型，不抢占 | 用户正在用时不能突然换模型 | 定时任务换到自己的模型，用完换回 |
| 运行位置是全局设置，不按对话单独存 | 用户只需要记住一个状态，隐私信号也只有一种 | 按对话存，更灵活，但同屏可能出现两种承诺 |
| 切换运行位置用撤销，不弹确认 | 切换时还没有内容离开，真正发送时对话里留标记 | 切到远程前弹确认，更醒目但多一步 |
| 失败时绝不自动换运行位置 | 自动转到远程会把内容送出设备 | 自动回退，更省事但违背隐私承诺 |
| 想用本机服务的进阶用户，把远程地址填成 `127.0.0.1` | 少一种运行位置，文案仍然真实 | Web 上单独提供“本机服务”选项 |

## 待定

按影响排序。

### 1. 手机和浏览器能跑多大的模型

决定“全能”的推荐条件，以及实时在手机和浏览器上的可用范围。真机验证已延后，方法见 [平台落地](07-platforms.md#模型下载与内存)。结果可能改变欢迎流程。

### 2. 场景和 Agent 分发

用户想借鉴 skills 的方式，细节未定。现状只有 `source` 字段和稳定 ID。

方向建议：场景是可安装的包，内容包括名称、说明、建议、提醒频率、所需权限和翻译。

设计上要先回答：

- 安装时怎么显示它要的权限和是否联网。
- 第三方场景能否调用工具。一旦能，“内容不离开设备”就不再由我们单方面保证。
- 谁能发布，怎么审核，怎么更新。
- 场景和 Agent 的关系：用户看到的是一个东西还是两个。

### 3. 粤语

香港用户说粤语时，识别和语音回答能否支持，取决于模型能力。不支持时要想清楚 `zh-Hant-HK` 的语音回答默认说什么。

### 4. 记忆写入敏感信息

健康、证件、财务信息写入记忆前要不要询问。

### 5. 医疗和法律类回答

体检报告是核心场景。现在靠回答文字提示“以医生意见为准”。要不要有界面级的固定提示，以及模型能力边界怎么说。

### 6. 增强对比度和色盲模式

双轨波形靠位置区分，不依赖颜色。其余状态有文字。增强对比度的色值未定义。

### 7. 提示音制作

规格是提议，尚无素材。
