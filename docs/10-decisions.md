## 本轮提议，等你确认

这些已经写进文档或原型，改起来都容易。

| 提议 | 理由 | 替代方案 |
|---|---|---|
| iOS 后端优先候选为社区 LES + Apple 模块的混合实现；先做最小 Core AI 实验，按结果决定是否转向 Core AI 中心运行时 | 保留成熟专家 I/O 与量化实现，把研究投入放在可验证的平台收益上；动态专家输入有官方示例，完整 iOS 配方与组合性能仍待验证。见 [路线对比](../experiments/ios-inference-options.md) | 社区 LES 深度演进；或实验支持后采用 Core AI 中心实现。尚未选定后端 |
| 联网搜索默认“每次询问” | 搜索词是唯一可能带用户信息离开的内容 | 默认关闭，更严格，但能力不可发现 |
| 手机第一版没有屏幕共享 | iOS 上后台没有 GPU，手机网页不支持 | 只在远程模式或 Android 上提供 |
| Android 第一版用静态配色 | 动态配色可能破坏朱砂的含义 | 动态配色 |
| 不用拟人形象 | 模型由声音、波形和文字表达，也减少过度信任 | 给模型一个形象 |
| 欢迎流程不要权限 | 用到时才问 | 一次要完 |
| 原生端破坏性操作用系统红色 | 让朱砂更专注于采集状态 | 全部用朱砂 |
| 降温回升保持自动 | 只是恢复用户同意过的采集范围；暂停之后才要点击 | 每次都要点击，更严格但很烦 |
| 去掉“默认模型”，合并成“当前模型” | 只剩一个模型时两个概念重复。下次打开沿用上次的 | 保留默认模型，作为打开时载入的那个 |
| 确认后立刻开始换，不等到发送时 | 等待在用户打字时就过去了 | 发送时才换，等待来得突然 |
| 需要别的模型时先问，不自动换 | 换模型影响所有对话，还要等待 | 自动换，少一步但用户不知道发生了什么 |
| 载不下时换回原来的模型 | 用户不会落到没有模型可用的状态 | 停在未载入状态，等用户处理 |
| ~~定时任务用当前模型，不抢占~~ **已替换** | 2026-11-06 决定不做后台计算，定时任务改成定时通知 | |
| 运行位置是全局设置，不按对话单独存 | 用户只需要记住一个状态，隐私信号也只有一种 | 按对话存，更灵活，但同屏可能出现两种承诺 |
| ~~切换运行位置用撤销，不弹确认~~ **已替换** | 2026-11-12 决定在线备用开启前要说明并取得同意。切回本机仍用提示和撤销。对话里的标记保留 | |
| 失败时绝不自动换运行位置 | 自动转到远程会把内容送出设备 | 自动回退，更省事但违背隐私承诺 |
| 想用本机服务的进阶用户，把远程地址填成 `127.0.0.1` | 少一种运行位置，文案仍然真实 | Web 上单独提供“本机服务”选项 |
| iCloud 备份默认关闭，开启时就地确认 | 第一条承诺是内容不离开设备，备份是用户选的例外。上传没法撤销 | 默认开启，省事但违背承诺 |
| iCloud 备份用应用自己的方案，系统自动备份排除 | Mac 没有系统的云备份，用户也管不到系统备份的内容 | 直接放进系统备份，简单但 macOS 没有，也不可控 |
| 备份跟随本机，不留历史版本 | 这里删掉的内容不该留在云端 | 留历史版本，能找回但删除不彻底 |
| 模型类型叫“全能”“看图”，规格叫“轻量”“完整” | 原来“轻量”指视觉模型，和规格撞词 | 类型叫“视觉”，更准但不够白话 |
| 推荐内存够用的最大规格 | 先用简单规则占住接口 | 总是推荐轻量，下载更快，之后再升级 |
| 一个模型只留一种规格 | 省空间，用户不用分辨两份 | 允许并存，切换快但占空间 |
| 备忘录走系统分享面板 | 写入提醒事项要读取全部提醒的权限 | 用 EventKit 直接写入，少一步但权限过大 |
| 朱砂只表示采集：暂停、静音时退掉，语音实时加采集点，话轮灯不用朱砂 | 让“有没有在听”只有一个答案 | 保持静音按钮朱砂，更醒目但语义冲突 |
| 离线模式优先于运行位置 | 用户明确说了不联网 | 远程不受离线模式影响 |
| 记忆和参考音频在远程时随请求发送，文案写明 | 不发送就用不上，发送就要说 | 远程时不用记忆，更保守但回答变差 |
| “已记住”一行撤销不限时，撤销后不再显示原文 | 用户收回一条记忆，是想让它消失 | 保留原文，方便回看 |
| 低电量门槛：低电量模式或不到 20% 放慢，不到 10% 只用声音，不到 5% 暂停，充电时不算 | 先用简单规则占住位置，实机再调 | 只看系统低电量模式，简单但 Web 没有这个信号 |
| 电量暂停后随时可以继续 | 这不是保护设备，决定权在用户 | 接上电源才能继续，更省电但可能卡住用户 |

| 崩溃报告的询问放在横幅，不放对话流 | 报告属于应用，不属于某段对话，也不该进备份和导出 | 放在对话里，和联网询问同样的卡片 |
| 第一阶段所有端的目录都只有看图模型，全能模型留到下阶段 | 实时推迟后，全能模型剩下的是语音消息和语音回复，一起放到下阶段，规则简单 | Web 连远程时先提供全能模型的轮流对话 |
| 输入框为空时，紧凑形态的主按钮是拍照提问 | 看图基线第一屏要有主动作，位置和全能基线的实时相同 | 保持灰色的发送按钮 |
| 看图基线的麦克风是说话输入，只在系统能本机识别时提供，Web 不提供 | 看图模型听不了声音，但“说一句”仍是常见路径。Web 的语音识别会把音频发出去 | 没有语音入口 |
| 说话输入完成后文字进输入框，不自动发送 | 系统识别也会错，用户看过再发 | 说完直接发送，少一步 |
| 紧凑形态的 Web 历史改成整页，返回手势关闭最上层 | 原生端是列表详情，Web 向它的操作靠 | 保留抽屉 |
| 高清细节移到模型设置，看图和实时共用 | 第一阶段没有实时设置页。官方三端都把这个放在显眼位置，默认最清晰 | 留在实时设置，第一阶段看不到 |
| 图片加进来就开始处理，写“正在处理”，可以发送 | 官方要等处理完才能发。发送后接上，和“正在准备”一致 | 处理完才能发送 |

### 1. 手机和浏览器能跑多大的模型

决定下阶段全能模型的推荐条件，以及实时在手机和浏览器上的可用范围。真机验证已延后，方法见 [平台落地](07-platforms.md#模型下载与内存)。第一阶段的列表由 backend 按硬件给出，不等这个结果。

公开的全能模型 Q4 全部模块约 8.3 GB，比原型的 6.0 GB 大，这个问题比之前估计的更紧。

### 2. 场景和 Agent 分发

用户想借鉴 skills 的方式，细节未定。现状只有 `source` 字段和稳定 ID。

方向建议：场景是可安装的包，内容包括名称、说明、建议、提醒频率、所需权限和翻译。

设计上要先回答：

- 安装时怎么显示它要的权限和是否联网。
- 第三方场景能否调用工具。一旦能，“内容不离开设备”就不再由我们单方面保证。
- 谁能发布，怎么审核，怎么更新。
- 场景和 Agent 的关系：用户看到的是一个东西还是两个。

### 3. 粤语

香港用户说粤语时，识别和语音回答能否支持，取决于模型能力。不支持时要想清楚 `zh-Hant-HK` 的语音回答默认说什么。

### 4. 记忆写入敏感信息

健康、证件、财务信息写入记忆**之前**要不要询问。写入后看得见、撤销得了已定。

### 5. 医疗和法律类回答

体检报告是核心场景。对照原图解决了“读错”，回答文字提示“以医生意见为准”。要不要再有界面级的固定提示，以及模型能力边界怎么说。

模型能否给出数字在图上的位置和把握程度 **[待实测]**。给不出位置时，对照原图退回到“整张图加读到的原文”，给不出把握程度时不显示“看不太清”。

官方 iOS 的 OCR 管线能给区块位置和检测分数（`refs/minicpm-v-apps/MiniCPM-V-demo/Sources/Base/Model/OcrEngine.swift@d0dd7a6`），精度到区块，不到单个数字。它是单独的模型，只在 iOS，要和“一次只运行一个模型”协调。要不要作为“读文档”进入产品，待定。

### 6. 增强对比度和色盲模式

双轨波形靠位置区分，不依赖颜色。其余状态有文字。增强对比度的色值未定义。

### 7. 提示音制作

规格是提议，尚无素材。

### 8. 导出文件格式

用户决定有导出和导入，格式待定。要回答：是否加密、附件怎么放、版本怎么升级，以及要不要让其他工具能读。

### 9. Android 和 Web 的备份目标

所有平台都要有备份，但这两端的目标还没想好。现在只有导出和导入。

### 10. 能力基准

多页文件、多张图、长对话的遗忘提示都依赖最终适配的能力基准。引擎现在“只取一张图、保留最近 8 条”，界面可以选多个文件。基准明确之前不细化，现阶段先看整体交互逻辑。

视频也在这里定。官方客户端不超过 64 帧、每秒 1 帧，iOS 处理视频前清掉上文，也就是视频不带前面的对话。这要写给用户，否则和“对话是唯一的容器”矛盾。

### 11. 留到开发前的状态

- 读屏的朗读声可能被全双工模型当成用户说话（推断）。
- Web 打开两个标签页时，可能各载一份模型。
- Web 没有应用锁和加密，而它是 Windows 和 Linux 的主要交付方式，共用电脑时要说明。
- 重连失败还没有状态参数。它和模型重启失败是同一条路径，加参数只要一行。

### 13. 场景包的最小字段

MobileCPM 的智能体只有名称、头像、提示词、开场白、模型五个字段。纯提示词的场景不调用工具，不影响“内容不离开”，可以作为待定 2 的第一步。
