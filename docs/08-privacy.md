# 隐私设计

隐私是这个产品的主要卖点，所以它是一套界面行为，不是一个设置页。

## 三个承诺

欢迎页的三句话是产品对用户的约定，所有设计都不能违反：

1. **内容不离开这台设备。** 声音、画面和文件都在本机处理。只有你同意时，搜索词、在线备用或备份才会离开。
2. **断网也能用。** 模型下载好之后不需要网络。
3. **都由你决定。** 记住了什么、联网做了什么，都能看到和删除。

第一阶段只有看图模型，文案跟着能力走：写“能看图、读文档”和“图片和文件都在本机处理”，不写声音和画面。

开启在线备用或 iCloud 备份时，第一条不再完全成立。这时所有声明都要改成写明发送到哪里，见下文。界面上叫“在线备用（可选）”，规则层的运行位置仍是远程（`remote`）。

Web 上模型跑在浏览器里，第一条同样成立。第二条要求页面能离线打开，见 [平台落地](07-platforms.md#web-特有)。浏览器扩展能读页面内容，这不在应用的控制范围内 **[推断]**，要写进隐私说明。

## 信号

用户任何时候都能回答这三个问题。

| 问题 | 信号 | 位置 |
|---|---|---|
| 内容在哪里处理？ | 本机处理 / 内容会发送到 example.com | 新对话、紧凑标题、取景标签、对话详情第一项、设置 |
| 现在有没有在听、在看？ | 状态灯、状态词、朱砂框、“模型看不到画面”、“没有在听” | 控制条、取景 |
| 有什么离开过设备？ | 联网记录 | 设置，对话里的记录行 |

系统自己的信号是兜底：iOS 橙点和绿点，Android 隐私指示器，macOS 菜单栏的点。应用内信号不替代它们，也不和它们矛盾。

## 规则

### 采集

- 采集开始前用户一定有明确动作。
- 系统造成的停止和闲置超时之后，恢复要用户点击。详见 [实时会话](04-live-session.md#打断暂停)。
- 画面默认不保存，转写默认保存，都可以改。
- 耳机断开时暂停，防止回答被外放。
- 长时间没说话自动暂停，防止忘记关闭。
- 手机上实时中暂停通知，避免通知内容被画面或录屏带走。

### 权限

- 用到时才问，问之前说明用途和处理位置。
- 被拒绝时给出路径，同时给替代方案：“在系统设置里允许后重试，或者先用文字继续”。
- 设置页列出每项权限的状态，管理按钮跳到系统设置。
- 说话输入用系统的语音识别。只有系统能保证在本机识别时才提供，否则不出现，这样“本机转成文字”才是真的。Web 不提供。

### 联网

默认只有三类请求，都不含用户内容：检查更新（只发送版本号）、模型下载、用户同意的崩溃报告。匿名使用统计默认关闭。不做追踪，不接第三方统计或广告 SDK，所以这项在真正发出请求之前不算第四类。一旦要发送，必须先取得同意，并重新做隐私营养标签，不能直接接统计 SDK。

崩溃报告默认每次询问，只含设备型号、应用版本和出错的位置，发送后记进联网记录。询问的方式见 [实时会话](04-live-session.md#意外退出之后)。实现时用 Xcode Organizer 或 MetricKit。接第三方崩溃 SDK 会打破“不收集数据”的目标，见 [开发期合规](12-compliance.md#隐私营养标签争取不收集数据)。

用户内容离开设备只有三种情况：

| 情况 | 控制 |
|---|---|
| 联网搜索 | 默认每次询问。卡片写明要发送的那句话，点了才发 |
| 在线备用 | 默认关闭。开启或更换地址前说明发送什么、发给谁，取得同意。全程写明目的地，每条回答都有标记 |
| iCloud 备份 | 用户开启，默认关闭，见 [备份与导出](#备份与导出) |

离线模式关闭全部联网，包括更新、搜索、模型下载、在线备用和备份。它优先于运行位置：在线备用开着时再开离线模式，不发送，横幅提供关闭离线模式或改用这台设备，不自动切换。

**联网搜索只发送搜索词。** 对话内容、文件、声音和画面都不发。搜索词由模型生成，可能带上用户的信息，所以要展示给用户确认。“自动”档存在这个风险，默认不开，选择时要提示。

**联网记录**列出最近 7 天的所有请求。有内容离开时，顶部的声明也要改，不能继续写“没有内容离开”。在线备用和 iCloud 备份各占一行，写明发送什么、发到哪里。走了备用通道的每一条还要有时间、目的地和内容类型。

### 记录与记忆

| 内容 | 默认 | 控制 |
|---|---|---|
| 对话记录 | 保存 | 可关闭，可自动清理（7、30、90 天） |
| 实时转写 | 保存 | 可关闭 |
| 实时画面 | 不保存 | 可开启 |
| 定格画面 | 作为附件保存 | 可模糊人脸 |
| 记忆 | 开启 | 可关闭，逐条查看和删除 |
| iCloud 备份 | 关闭 | 用户开启，可关闭，可删除云端副本 |
| 临时对话 | 不保存，不写记忆 | 对话内开关，可设为默认 |

写入记忆时，对话里留一行“已记住：……”，当场能撤销，也能进入管理。这一行读的是实际保存的内容，在设置里删除后它变成“已忘掉这条”，不再显示原文。

“健康”“证件”这类敏感信息写入**之前**要不要询问，是待定问题。现在是写入后看得见、撤销得了。原型示例里有“你对青霉素过敏”，它有价值，也敏感。

### 访问

| 项目 | 说明 |
|---|---|
| 打开时验证 | 面容、指纹或系统密码。锁定页只有标记和解锁按钮 |
| 自动锁定 | 立即、1 分钟、5 分钟、不锁定 |
| 后台遮盖 | 最近使用的应用里只显示品牌标记 |
| 录屏和截屏 | Android 可以禁止。iOS 没有公开方法，录屏时遮盖内容 |
| 加密保存 | 用设备密钥 |

### 通知

通知内容在锁屏上可见，所以默认不写对话内容。

| 通知 | 文案 |
|---|---|
| 定时通知 | 用户在卡片上确认过的那句话，比如“该整理社区消息了” |
| 下载完成 | MiniCPM-o 4.5 准备好了 |
| 暂停的实时会话 | 实时会话已暂停 |

用户可以在系统设置里选择显示预览。定时通知的内容是用户自己确认过的一句话，锁屏是否显示由系统的预览设置决定。

### 删除

- 单条对话和记忆可撤销，7 秒内。对话里“已记住”那一行的撤销不限时。
- 清除全部不可撤销，这是少数需要确认的操作，写清范围。开启在线备用、开启 iCloud 备份也用确认，不用事后撤销代替。
- 首发前要有一键“删除全部数据（含模型与设置）”。现在只有清除全部对话、逐条删除记忆，以及卸载时一起删掉模型文件。
- 临时对话清除没有撤销。
- 卸载应用等于删除全部，模型文件也一起删除。iCloud 里的备份还在，要在 iCloud 设置里或重装后删除 **[待实测]**。

## 备份与导出

对话有备份需求，但备份会让内容离开设备，所以它是用户主动打开的例外。

| 项目 | 规则 |
|---|---|
| 默认 | 关闭。系统的自动备份也排除，见 [平台落地](07-platforms.md#备份) |
| 开启 | 就地确认，写明“对话记录会离开这台设备，存到你的 iCloud”。上传没法撤销，所以这里不用撤销，用确认 |
| 内容 | 对话、转写、材料、已记住的内容 |
| 不包括 | 模型文件、临时对话、访问令牌、设置过的参考音频 |
| 方式 | 跟随本机：这里删掉的对话，下次备份时云端也删除。没有历史版本 |
| 关闭 | 立刻停止，可撤销，云端副本保留，提示可以删除 |
| 删除云端副本 | 就地确认，不可撤销，不影响本机 |
| 失败 | 只在设置里显示，不打断使用。写明空间不够或没有登录，给系统设置入口 |
| 离线模式 | 备份暂停 |
| 恢复 | 只取回本机没有的对话，不覆盖。新设备第一次打开时询问 |

**声明要跟着变。** 开启后，新对话写“只在这台设备上处理，记录备份到你的 iCloud”，隐私页和联网记录写明备份，模型选择器的“内容不离开本机”改成“在本机处理”。

**导出**把对话存成一个文件，所有平台都有，是 Android 和 Web 目前唯一的迁移方式。文件里有对话全文，离开了应用锁的保护，所以说明里写“由你保管”。**导入**不覆盖现有对话，重复的跳过，结果写明导入和跳过的数量，可撤销。文件读不了时写原因，现有对话不变。

格式待定，见 [决策记录](10-decisions.md)。其他备份目标也待定。

## 在线备用

界面上叫“在线备用（可选）”。规则层的运行位置仍是“这台设备 / 远程”。第一版默认用这台设备。在线备用默认关闭，是这台设备跑不了或用户自己要换时的备用通道。开启或更换地址之前必须先说明并取得同意，不能只靠切换后的撤销。同意之后，文案必须如实变化。

| 位置 | 本机 | 在线备用 |
|---|---|---|
| 新对话 | 只在这台设备上处理，内容不会离开 | 内容会发送到 example.com 处理 |
| 取景标签 | 本机处理 · 每秒看 1 帧 | 正在上传 · 每秒看 1 帧 |
| 紧凑标题 | 本机 | 远程 |
| 发送前 | 无 | 输入框旁写“将发送到 example.com” |
| 每条回答 | 无额外标记 | 回答下方写“经 example.com 处理”。读屏从“AI 回答”读起 |
| 开始实时 | 无额外提示 | 提示声音和画面会发送到哪里 |
| 对话详情 | 这台设备 | 服务器地址 |
| 设置 | 你的内容留在这台设备上 | 内容正发送到 example.com |
| 切换后的对话 | 从这里开始只在这台设备上处理 | 从这里开始发送到 example.com 处理，上文也包括在内 |
| 联网记录 | 没有内容离开这台设备 | 内容正发送到 example.com，并列出一行 |
| 已记住的内容 | 只保存在这台设备上 | 保存在这台设备上，用得上的内容会随请求发送到 example.com |
| 参考音频 | 只保存在这台设备上 | 保存在这台设备上，生成声音时会发送到 example.com |
| 还没填地址 | | 还没设置在线备用，内容不会发送 |
| 离线模式开着 | 端侧功能可用 | 显示“离线中，未发送” |

开启和切换的规则：

- 首次开启，或地址和上次同意的不一样时，先打开说明页。写清发送什么（这次对话的文字、附加的图片和文件）、发给谁（地址和运营方，并链接对方的隐私政策）、什么时候发（这台设备跑不了，或用户选择走备用时）。按钮是“开启并同意”和“暂不开启”。
- 记下同意过的地址和时间。关掉立即停止发送。更换地址要重新同意。
- 切回这台设备时，内容还没继续外发，用提示和撤销。
- 已有内容的对话，同意页和切换标记都要写明上文会一起发送。
- 每条走了备用通道的回答都留标记，不能删，事后能看出哪部分离开过设备。
- 离线模式优先于运行位置。
- 失败时绝不自动换运行位置。横幅上的“改用远程服务”和欢迎页的“连接远程服务”走同一步同意。

访问令牌只进系统安全存储，界面只显示“已保存”。直连用户填写的地址，不经过开发者自己的代理。运营方做不到处理完即丢弃时，不能再把隐私营养标签填成“不收集数据”。

## 应用商店披露

目标是 iOS 隐私营养标签“不收集数据”：端侧处理不算收集；在线备用、联网搜索、下载和更新检查都要做到不留存。用户自愿开启的功能如果会收集，同样要申报。判断表和 Privacy Manifest 见 [开发期合规](12-compliance.md)。发布前要填的账号、链接和供应范围见 [首次发布与商店政策](13-release-and-store-policy.md)。

| 平台 | 需要准备 |
|---|---|
| iOS | `NSMicrophoneUsageDescription`、`NSCameraUsageDescription`、相册和语音识别的用途说明，放进 `InfoPlist.xcstrings`。`PrivacyInfo.xcprivacy` 里 `NSPrivacyTracking` 为 false，收集类型为空。隐私营养标签目标是不收集数据。审核指南 2.5.14 要求录制有同意和明确提示。不做追踪，不需要 ATT |
| Android | Data safety 表单，前台服务类型声明 |
| Web | 隐私政策说明 localStorage / IndexedDB / OPFS 只存功能数据。不加统计就不做 cookie 同意横幅 |

用途说明文案和应用内权限说明保持一致。占位链接（`https://example.com/privacy` 等）集中在一处，发布前再换成正式地址。
